# 서울 정비사업 지도

NAVER Maps Client ID `zhvmg0rp93`을 반영한 로컬 실행용 지도입니다. 실제 서울시 SHP 경계를 WGS84 GeoJSON으로 변환했습니다. 실행에는 데이터 변환용 라이브러리를 설치할 필요가 없습니다.

## Mac에서 실행

1. ZIP 압축을 풀고 `seoul-renewal-map` 폴더를 원하는 곳에 둡니다.
2. 터미널에서 해당 폴더로 이동합니다. 다운로드 폴더에 압축을 풀었다면:

```sh
cd ~/Downloads/seoul-renewal-map
python3 -m http.server 8000
```

3. 브라우저에서 http://localhost:8000 에 접속합니다. 파일을 더블클릭하는 방식은 지원하지 않습니다.
4. 서버를 종료하려면 터미널에서 Control+C를 누릅니다.

`Address already in use`가 나오면 기존 8000번 서버를 실행한 터미널에서 Control+C로 종료한 뒤 이 폴더에서 다시 실행하세요. 작업 당시 8000번에 다른 앱이 실행 중이어서 해당 서버는 변경하지 않았습니다.

지도는 인터넷 연결이 필요합니다. NAVER Cloud의 Dynamic Map과 Web Service URL `http://localhost:8000` 설정이 필요합니다. `127.0.0.1`이나 다른 포트로 접속하면 그 주소도 별도로 등록해야 할 수 있습니다. Client ID는 브라우저용 공개 식별자이며 Client Secret은 사용하지 않습니다.

## 포함된 기능

- 구역명 검색(공백 무시), 한남·성수·압구정·반포·방배 바로가기
- 자치구·사업유형·사업단계 복합 필터, 검색 결과 지도 맞춤
- Polygon/MultiPolygon 및 내부 구멍을 포함한 NAVER Data Layer
- 경계·목록 클릭 팝업, 상세정보, 공식 출처 링크
- 모바일 세로 배치, 목록 접기, 범례, 로딩·오류·빈 검색결과 안내
- 지도 API가 실패해도 검색·필터·목록 상세정보 이용 가능

### 정보 해석

- 952건은 고유 사업 수가 아니라 **분류별 공간자료 행 수**입니다. 동일 지역의 재개발·재건축과 신속통합기획이 겹칠 수 있습니다. 원본을 임의로 합치지 않았습니다. 유형 필터와 목록을 이용해 각각 확인하세요.
- 경계는 서울시가 제공한 실제 사업 공간자료입니다. **법적 효력이 없으며**, 신속통합기획 대상지·모아타운은 법정 정비구역과 다를 수 있습니다.
- 사업단계는 DBF의 `PROPEL_CD`를 같은 ZIP의 공식 코드표로 해석했습니다. 실시간 단계로 표시하지 않습니다.
- 한남 등 이름이 정확히 같은 재정비촉진구역(BZ402) 항목은 단계 비교용으로 상세정보에 추가했습니다. 기재 단계가 다르면 어느 하나를 최신으로 추정하지 않습니다.
- 세대수는 원본에 항목이 없어 전부 `null`/자료 없음입니다. 다른 단지의 수치나 기사 수치를 대입하지 않았습니다.
- 면적은 `DGM_AR` 원본 기재값이며 경계에서 다시 계산한 면적과 다를 수 있습니다. 0은 미확인으로 표시합니다.
- `CREATE_DAT`는 원본 날짜 필드로만 표시합니다. 인허가일이나 최종 사업정보 갱신일로 간주하지 않습니다.
- 공식 사업정보 확인: https://cleanup.seoul.go.kr/ (구역명으로 검색). 개별 사업 페이지와 검증된 연결키가 없어 통합 홈페이지 링크임을 명시했습니다.
- 원본의 자기교차 경계 **신림6구역, 청담삼익아파트**는 자동 보정 없이 제외했습니다. 원본 ID와 이유는 `data/metadata.json`에 기록했습니다.

### 이용조건

원본 페이지에 명시된 이용허락은 **공공누리 제4유형: 출처표시·상업적 이용금지·변경금지**입니다. 서울특별시 출처와 조건을 유지하세요. 이 폴더는 요청한 로컬 참고용으로 제공하며, 경계 단순화·임의 수정 없이 좌표계·파일 형식 변환과 대상 분류 추출만 수행했습니다. 공개 재배포나 상업적 활용 시 원본 이용조건 및 변환물 이용 가능 범위를 제공기관에 확인하세요. 지도 API에는 NAVER의 이용조건이 별도로 적용됩니다.

## 파일 구성

- `index.html`, `app.js`, `style.css`: 지도 화면

- `VALIDATION.md`: 검증 결과와 남은 확인사항

## 데이터 업데이트

1. 위 공식 자료 페이지에서 새 ZIP을 내려받아 `original/`에 저장합니다. 파일 수정일과 원본 파일명을 기록합니다.
2. **업데이트 작업을 할 때만** Python 라이브러리를 설치합니다.

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r tools/requirements.txt
python tools/convert.py original/seoulplan-202609.zip --release-date 2026-09-10 --source-filename '532_UQ120_도시계획사업(서울플랜+)_202609.zip'
```

새 파일은 위 명령의 경로·날짜·파일명을 바꿉니다. 서버 실행에는 가상환경이 필요하지 않습니다. 변환 후 브라우저를 새로고침하세요. SHP 필드나 코드표 구조가 변경되면 변환 도구의 매핑을 먼저 점검해야 합니다.

원본 `.prj`를 pyproj로 해석합니다. 원본 좌표계는 Korean 1985 Modified Korea Central Belt이며 WGS84(EPSG:4326), 경도·위도 순서로 변환합니다. 단순화·buffer 보정·추정 좌표 생성은 하지 않습니다. 외곽/내부 링 방향만 GeoJSON 관례에 맞춥니다. 도형 내부 대표점은 팝업 위치에만 사용하며 사업 중심점 같은 공식 속성이 아닙니다.

다른 공식 자료에서 세대수 등을 보강할 때는 구역명만으로 자동 연결하지 말고 사업 ID·자치구·사업 범위와 기준일을 검증한 뒤 필드별 출처·기준일을 함께 저장하세요.
